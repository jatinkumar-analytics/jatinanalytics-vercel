01 / PROJECT OVERVIEW

From cloud files to trusted analytical models.

The source data contains 5,000 bookings, 500 listings and 200 hosts. The files were stored in AWS S3, loaded into Snowflake and transformed through a modular dbt project.

The project contains 11 models across Bronze, Silver and Gold, plus two history-preserving snapshots. The final reporting layer provides one booking-grain Fact table, three Dimensions and an optional wide table for ad hoc analysis.

Core objective: preserve source traceability, make transformation logic reusable, validate analytical relationships and expose a clear star-schema grain.

02 / LAND & LOAD

Cloud source and warehouse setup.

Three source-aligned CSV datasets were stored privately in AWS S3 and loaded into Snowflake staging tables. The raw source was not manually edited before transformation.

03 / TRANSFORMATION LAYERS

Layered transformations with reusable business logic.

BRONZE

Source aligned

One-to-one models for Bookings, Listings and Hosts preserve source structure and traceability.

SILVER

Clean and enriched

Reusable Jinja calculations, incremental merges, latest-record deduplication, standardisation and business segmentation.

SNAPSHOTS

History preserved

Two SCD Type 2 snapshots retain historical Listing and Host attribute versions.

GOLD

Analytics ready

A booking-grain Fact, three Dimensions and an optional OBT support analytical consumption.

Silver enrichment

Bookings calculate total and grand-total amounts through reusable macros. Listing and Host models use incremental merge logic, keep the latest record per business key and add fields such as price_per_guest, price and capacity segments, host tenure, response-quality bands and host segments.

Invalid listing conditions are flagged in data_quality_status instead of being silently deleted.

04 / DIMENSIONAL MODEL

A booking-grain Fact connected to three Dimensions.

FACT_BOOKINGS contains one row per booking and connects to Listing, Host and Date Dimensions through analytical keys. Historical versions remain available through snapshot tables.

DATASET LIMITATION

Reporting the source data responsibly.

Approximately 49% of the supplied booking records are cancelled. Because this is a learning dataset, this rate is not treated as representative of real Airbnb operations.

For production reporting, completed bookings, cancellations, refunds and cancellation reasons should be modelled separately before calculating executive revenue KPIs.
